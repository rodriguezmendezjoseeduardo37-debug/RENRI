🚀 3-STEP QUICK START
═══════════════════════════════════════════════════════════════════════════════

STEP 1: Execute RLS Script (5 minutes)
─────────────────────────────────────
1. Open: https://app.supabase.com/project/<your-project>/sql/new
2. Copy ALL content from rls-policies.sql
3. Paste in SQL Editor
4. Click RUN
5. Wait 30 seconds
6. See "✓ Compiled successfully" message

Expected Output:
  ✓ 8 tables with RLS enabled
  ✓ 32+ policies created
  ✓ 2 helper functions created
  ✓ Verification queries executed


STEP 2: Verify Setup (2 minutes)
───────────────────────────────
1. Open SQL Editor > New Query
2. Copy this query:

   SELECT tablename, rowsecurity 
   FROM pg_tables 
   WHERE tablename IN ('users', 'appointments', 'orders', 
                       'payments', 'products', 'schedules', 'turns', 'tenants')
   ORDER BY tablename;

3. Run it
4. ALL should show rowsecurity = TRUE

If FALSE:
  → Run: ALTER TABLE <table> ENABLE ROW LEVEL SECURITY;


STEP 3: Test in Your App (5 minutes)
────────────────────────────────────
1. Copy TypeScript code from auth-rls-integration.ts
2. Update your src/auth.config.ts JWT callback:

   jwt({ token, user }) {
     if (user) {
       token.tenantId = user.tenantId;  // ✅ Already there!
       token.role = user.role;          // ✅ Already there!
     }
     return token;
   }

3. Test with:
   
   const { data } = await supabase
     .from('appointments')
     .select('*');
   // Should return only user's appointments!

🔐 SECURITY FEATURES
═══════════════════════════════════════════════════════════════════════════════

After RLS:

Clients:
  ✅ Can see only THEIR notifications
  ✅ Can see only THEIR appointments
  ✅ Can see only THEIR orders
  ❌ Cannot see other clients' data
  ❌ Cannot see admin-only data

Admins:
  ✅ Can see all data in THEIR tenant
  ✅ Can manage appointments, orders, payments
  ❌ Cannot see data from OTHER tenants
  ❌ Cannot access SUPER_ADMIN features

Super Admin:
  ✅ Can see EVERYTHING
  ✅ Can modify anything
  ✅ System-level access

Anonymous:
  ❌ Cannot access ANY data

⚠️ TROUBLESHOOTING
═══════════════════════════════════════════════════════════════════════════════

Problem: "Permission denied for relation appointments"
→ Solution: Verify RLS is enabled
→ Run: SELECT rowsecurity FROM pg_tables WHERE tablename = 'appointments';

Problem: User can't see any data
→ Solution: Check JWT claims
→ Ensure: token.tenantId and token.role exist
→ Run: testRLSAccess('appointments', 'SELECT');

Problem: Admin can't see other users
→ Solution: This is CORRECT! Admins only see their tenant
→ Verify: admin.tenantId = data.tenant_id

Problem: Policies don't exist
→ Solution: Run rls-policies.sql again
→ Verify: SELECT COUNT(*) FROM pg_policies WHERE tablename = 'users';
